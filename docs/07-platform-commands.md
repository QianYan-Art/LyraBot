# 平台层与聊天命令

记录日期：2026-11-07（2026-11-09 自 `01-architecture.md` 拆出整理，2026-11-10 命名统一为 LyraBot）
范围：`lyrabot-platform`（QQ 官方、CLI）、`lyrabot-command`（命令解析与帮助）与运行时的命令执行（`apps/lyrabot/src/runtime/commands.rs`）。

## 1. 平台接口

`Platform` trait 负责运行收包循环（把入站消息送进 Inbox）、发送出站消息（带错误类别 `too_long / bad_format / forbidden / not_found / rate_limited / transient / unknown`）并声明能力（主动消息、分段、媒体类型）。Pacer 与投递逻辑按能力分支。

## 2. QQ 官方机器人（单聊）

- 鉴权：`POST https://bots.qq.com/app/getAppAccessToken {appId, clientSecret}`，到期前 60 s 刷新；网关 4004 时作废重取。API 头 `Authorization: QQBot <token>`，基址 `https://api.sgroup.qq.com`。
- 网关：`GET /gateway` 取 wss 地址；连接 20 秒、Hello 30 秒期限；Hello(op10) 后按间隔 80% 发心跳 `{"op":1,"d":<最新 seq>}`，连续两次未收到 ACK 即重连；有 session_id 与 seq 时 Resume(op6)，否则 Identify(op2，intents = 1<<25 | 1<<30 | 1<<12 | 1<<26)；op7 重连并 Resume（QQ 约每小时要求一次，1–2 秒内恢复）；op9 不可恢复时清会话重新 Identify。致命关闭码 4001/4002/4010/4011/4012/4013/4014/4914/4915 停止重连并让进程退出（由 systemd 处理）；4006/4007 清会话；4008 等 60 s；其余按 1/2/5/10/30/60 s 退避，连接稳定超过 60 s 后退避归零；连接关闭时立即返回进入重连，不空转。
- 入站：只处理 `C2C_MESSAGE_CREATE`，只接受唯一的 `allowed_users`（必须恰好一个，单用户设计），按 msg_id 去重（最近 200 条）。附件在后台流式下载（不阻塞心跳，同时最多 2 个，单个 60 s 超时，大小上限 50 MB，先写 `.part` 临时文件并由守卫清理半截文件，超限时在文本中如实注明）：图片落盘并以 `file://` 引用，请求时才由传输层转为 data URI（数据库不存 base64，缓存清理后显示“已清理”）；语音取 QQ 的 `asr_refer_text`；视频与文件落盘并在文字中写明路径。
- 出站路由（`reply::ReplyState`）：以用户最近一条消息为锚点被动回复（窗口 60 分钟、最多 5 次、msg_seq 1..5 递增）→ 主动消息许可事件的 event_id（拒收事件同时清除旧锚点）→ 主动消息（每月额度，北京时间；轮到主动通道时先在 `quota` 表原子占用一次，发送失败归还，并发发送不会超额）→ 都不可用时写入 SQLite 发件箱。主动消息被拒（Forbidden）同样转入发件箱。出站逻辑在 `qq/courier.rs`。
- 发件箱：`outbox` 表，文字与每个媒体各占一条，上限 50 条；用户下次说话后在后台串行补发，不阻塞网关收包。文字入箱前按 1500 字切块，相邻文字合并为不超过 1500 字的批次，逐批确认；合并后被判超长则逐条重发，单条仍被拒则保留；文件已不存在则跳过，上传失败或再次没有通道则保留到下次。
- 富媒体：本地文件 base64 内联上传 `POST /v2/users/{openid}/files`（≤9 MB，类型按扩展名 1 图片 / 2 视频 / 3 语音 / 4 文件），再以 msg_type 7 发送 `file_info`。超过 9 MB 的文件暂不能发送（分片上传见 `09-backlog.md`）。WAV 已实测可作为语音条发送；语音上传被拒时（其他格式）自动改按文件发送。图片上传前由 `qq/media.rs` 预处理（只处理静态 PNG/JPEG，APNG、GIF 等可能是动图的原样上传，不改动原文件）：体积超过 1 MB 或长边超过 2048 px 时先按 EXIF 方向摆正，再缩到长边 2048 内，不透明的转 JPEG（质量 88），含透明像素的保持 PNG；结果没变小就用原图。内存边界：解码输出（按实际色深计算）超过 128 MB 时不处理，解码器内部缓冲受同一上限约束，从解析文件头起同一时间只处理一张；读文件前先按大小拦截（图片 50 MB、其他文件 9 MB）。发送成功但响应里没有消息 id 时只记警告，不重发。取 token、网关地址与发消息的请求超时 30 秒，富媒体上传 120 秒。
- 运行：`lyrabot --qq`；SIGTERM/Ctrl+C 优雅退出。同一个 QQ 机器人同一时间只能连一个网关。
- 验证：协议由本地 WebSocket + wiremock 契约测试覆盖（Identify 载荷、READY、心跳 seq、过滤与去重、op7 后 Resume、被动回复 msg_id/msg_seq、媒体上传、致命关闭码、主动额度计数）；2026-11-08 起在服务器上实际运行。

## 3. CLI 与 OneBot

- CLI：本地开发与测试用，stdin 逐行输入，事件流式打印，支持全部 `/命令`；`--no-stream` 模拟 QQ 的分段发送；媒体以本地路径展示。
- OneBot（个人号）：只在能力位层面预留（poke、表情回应、自由主动消息），未实现适配器。

## 4. 聊天命令

原则：命令不经过模型、立即响应；每个命令只做一件事。命令与命令的回复都不写入主对话角色的会话，也不进入学习；只有已知命令才拦截，`/笑` 这类以 / 开头的普通说话照常交给主对话角色（2026-11-08 起）。参数不对时回复“参数不对”并附该命令的用法。

| 命令 | 作用 |
|---|---|
| `/help [命令]` | 按功能分组列出命令；带命令名看详细用法与说明条目 |
| `/status` | 版本、会话、模型与思考等级、上下文占用、用量与缓存命中、后台任务、内存、运行时长 |
| `/new` | 主对话角色开启新会话（记忆、关系不变，只是技术会话重开；旧会话标为已结束） |
| `/sessions [编号]` | 查看最近会话与数据库统计；带编号原子切回主对话角色的历史会话（沿用当时的记忆快照，需要最新记忆时发 `/compact`） |
| `/gc [天数]` | 清理已结束且超过 N 天（默认 30）没有活动的会话与已归档后台任务（含专员任务）；`/gc 0` 清理全部已结束会话与已归档任务 |
| `/stop` | 停止主对话角色当前这一轮并丢弃待合并消息（不影响后台任务） |
| `/compact` | 立即压缩当前会话（先折叠，不够再摘要）并刷新当前会话的记忆快照 |
| `/model [名称]` | 查看/切换主对话角色模型（须在模型目录中） |
| `/effort [等级]` | 查看/切换主对话角色思考等级 |
| `/learn` | 学习与记忆总览；`list 说法` / `list 记忆`（必须写明，不带对象视为参数错误）、`forget 编号\|u3\|m2`、`now`、`undo`、`on\|off` |
| `/agent [list]` | 列出后台任务与专员：编号、状态、模型、耗时、进度 |
| `/agent <id> [消息]` | 查看某个任务详情；带消息则续接/插话 |
| `/agent <id> stop` | 停止某个任务 |
| `/provider` | 列出生图/语音/搜索（含 grok）当前提供方与字段 |
| `/provider <类别> <字段> <值>` | 例：`/provider image model gpt-image-2.5-flare`；`use` 切换提供方；写回配置并热生效 |
| `/reload` | 重新加载配置、secret 文件与人格资产 |

- 定时任务由主对话角色的 `cron` 工具管理，没有单独的聊天命令；原设计中的 `/restart!` 未实现，进程重启由部署流程执行，重启时后台任务以“被中断”汇报交回。
- 抖音“确认发布 <plan_id>”与短信验证码在命令解析之前拦截（见 `06-tools-plugins.md` 第 3 节）。
- 每周自动清理一次（结束超过 30 天、且当时没有后台任务）；被较新会话引用的历史（fork 共享）暂时保留。

输出排版（2026-11-08/09）：QQ 单聊只显示纯文本、手机一行约 20 字，命令回复统一由 `lyrabot_core::card` 排版：标题带一个图标（📊 状态、📂 会话、🌱 学习、📖 帮助等），分节用「▍」，条目用「·」，操作提示每条一行各带「💡」，上下文占用显示十格进度条（全角 ■□）；手机 QQ 可能吞掉行首空格、部分安卓字体缺少少见符号，所以不靠缩进对齐，当前项用文字“（当前）”标出；一句话回复成功前缀 ✅、失败或无法执行前缀 ⚠️。token 显示为 `12.3k` / `1.0M`，不用 Markdown 与表格。一张卡片作为一条消息发送，不按空行拆分。
