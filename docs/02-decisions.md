# 关键决策记录（ADR）

记录日期：2026-11-07。决策来源：与阿颜的 grill-me 讨论。变更时追加新条目，不改写旧条目。

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | QQ 第一版沿用官方机器人 API，平台层预留 OneBot | 个人号 OneBot、两者同时 | 平稳替换现有项目；个人号有风控风险 |
| D2 | 纯 Rust 自研 pi 式内核 | 依赖社区 Rust 移植（pi_agent_rust、ri-agent-core、pi-rs）、Rust + Node 版 pi 旁路 | pi 是 TypeScript，且刻意不做子代理/MCP；社区移植均为 0.x、接口不稳定；自研可控，利于性能与长期运行 |
| D3 | 唐语歌单一门面 + 后台子代理 | 多 bot 并列、同一个模型切换模式 | 工具输出不污染角色上下文；角色与 agent 能力各自用最合适的提示词 |
| D4 | 子代理按任务派出、可续接，另设常驻专员 | 只按任务、只专员、用完即丢 | 兼顾 Muse 式持久上下文与临时任务的简单性 |
| D5 | 表达/黑话学习后台批处理，前台本地检索、≤150 token 尾注入 | 每轮调用模型规划、常驻大段提示 | 阿颜担心提示词开销影响角色内核 |
| D6 | 只接 kimi-code；模型目录、思考等级映射、传输格式配置化 | 多提供方 | 阿颜只用 kimi-code，需持续跟进官方变动 |
| D7 | 生图/语音/搜索/grok 做成可插拔提供方，QQ 命令可调；搜索换腾讯元宝搜索 | 全部内置写死 | 这几项经常换模型和服务方 |
| D8 | 抖音保持独立服务，内核直连其 Unix socket；通用外部工具用 MCP | 重写抖音、MCP shim | 现有服务稳定；服务端校验对端 PID 为网关 MainPID，shim 无法通过 |
| D9 | 语音识别用 QQ 自带 `asr_refer_text`，不常驻 whisper | 本地 whisper、工作站 | 省内存，Hermes 已验证该字段优先可用 |
| D10 | 开发期只用本地 CLI，一次性切换，Hermes 保留作回退 | 新测试机器人、分时段共用 | 阿颜选择；同一机器人不能并行两个网关 |
| D11 | 只做任务型主动消息 | 加闲聊式主动、不主动 | 受 QQ 主动消息额度限制 |
| D12 | 去掉 clarify、浏览器工具组、paper-translation-to-docx | 保留 | 阿颜确认 |
| D13 | 信任模型沿用 Hermes（不审批），只做审计与少数硬禁止 | 审批门 | 单用户，与现状一致 |
| D14 | Windows 上 cargo-zigbuild 交叉编译，服务器只放二进制 | 服务器编译 | 服务器 3.6 GB 内存，Rust 全量编译易 OOM |
| D15 | 切换稳定并经阿颜当次确认后，删除本地 `kimi.txt`、`yuanbao.txt` 并清理服务器 Hermes 项目 | 长期保留 | 阿颜要求；不可逆，执行前必须确认 |
