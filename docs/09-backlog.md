# 待做、推迟与未采纳

记录日期：2026-11-09（2026-11-10 命名统一为 LyraBot）
集中记录还没做的事：待做方向是已认可、以后可能做的功能；推迟是已识别但暂缓的工程改进；未采纳是评估后决定不做的方案。动手前先与用户确认，做完后从本文移除并写进对应模块文档。

## 1. 待做方向

- 识别用户引用的消息：用户在 QQ 里引用某条消息追问时，主对话角色目前只看到新消息的文字，看不到被引用的内容。做法：先在服务器抓一次真实的引用入站事件，确认 `C2C_MESSAGE_CREATE` 里表示引用的字段；出站时记录 QQ 返回的消息 id 与会话条目的对应关系（入站消息 id 已有）；入站解析出被引用的 id 后查出原文，在用户消息前加一句简短的“引用了：……”（截断到几十字）。只在引用时多几十个 token，不影响缓存前缀。

## 2. 推迟

- QQ 发送超过 9 MB 的大文件（分片上传）：当前出站单文件 ≤9 MB（一次性 base64 上传），日常图片、语音、日报均远小于此上限；若后续确有从 QQ 发送大视频或大归档的需求，再移植分片上传。
- 权限隔离：模型 shell 与抖音 socket 不做隔离。运行用户本就有免密 sudo，隔离需要另设执行用户，属架构调整。
- SQLite 读写分离与维护调度：目前读写同线程串行，出现读延迟问题再加只读连接。
- 通用 MCP 客户端：决定推迟，外部工具扩展口只保留在设计层面。
- OneBot（个人号）适配器：只预留能力位。
- grok 的 web_map 与 Tavily 兜底：未从 grok-search 移植。

## 3. 未采纳

- 向量检索与联想网络：需要常驻嵌入模型；记忆只有几千字，本来整份注入提示词。
- 情绪天气、“做梦”独白与主动开口：主对话角色不做闲聊式主动发消息的形态，有时间的事靠当场设定时提醒。
- MCP / context-mode 压缩工具输出：重活的工具输出本来就不进主对话角色的上下文，执行者侧已有折叠与输出落盘。
- `/restart!` 命令：进程重启由部署流程执行。
- 原设计的 `send` 工具：执行者媒体随〔后台结果〕由主对话角色那一轮发出即可。
- 机器人引用回复与撤回自己的消息：单聊一问一答，引用基本多余；说错了再发一句纠正比撤回更自然，做成可选开关也只会增加代码路径与配置。
